# Pattern: Bikeshedding (Law of Triviality)

**Topic:** `bikeshedding`  
**Pattern ID:** `P-001`

## Thesis
Bikeshedding is a predictable governance failure where attention flows to low-stakes, legible decisions while high-stakes, high-complexity work starves.

## Failure mode / principle
When participation is broad and the artifact is visible, discussion volume becomes inversely proportional to technical complexity.

## Conditions
- Large contributor set with uneven expertise
- High ambiguity or high complexity core decision
- Many “safe” opinions available on superficial details

## Symptoms
- Long threads about naming, formatting, colors, bikeshed-level choices
- Core safety/correctness issues deferred
- Burnout of domain experts

## Countermeasures
- Define decision scope + criteria up front
- Timebox aesthetics, prioritize risk-reduction work
- Explicit “decision owner” for non-core choices

## Modern analogs
- Open-source issues/PRs derailed by naming bikesheds
- Standards meetings dominated by terminology disputes
